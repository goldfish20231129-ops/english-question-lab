# School English Grammar and Corpus Evidence Guide V0.2

이 문서는 내신형 Provided Passage V0.2의 어법 품질을 보완하는 Knowledge다. Schema나 Contract를 확장하지 않으며, 실제 시험지·Corpus에서 관찰된 형식과 근거 사용 한계만 설명한다. 실제 기출 지문·선지·정답을 복제하는 자료가 아니다.

앱의 `grammarDesignProfile` 값, 문항별 구조 관찰표와 생성 절차는 `09-KNOWLEDGE-GRAMMAR-DESIGN-PROFILES.md`를 함께 따른다.

## 1. 감사한 실제 자료

2025학년도 고1 공통영어 시험지 세 종을 PDF 텍스트 레이어와 페이지 렌더링으로 함께 확인했다. OCR, 외부 사전, 웹 검색은 사용하지 않았다.

- 1학기 중간고사: 객관식 어법 7문항과 서술형 문장 교정 1문항을 확인했다.
- 1학기 기말고사: 객관식 어법 4문항을 확인했다.
- 2학기 기말고사: 객관식 어법 2문항을 확인했다.
- 합계: 객관식 어법 13문항, 서술형 교정 1문항이다.

감사 위치는 다음과 같다.

- 1학기 중간고사: Q3(p.1), Q5·Q7(p.2), Q11(p.3), Q18과 서술형4(p.5), Q20(p.6), Q24(p.7)
- 1학기 기말고사: Q7(p.2), Q12(p.4), Q19·Q20(p.5)
- 2학기 기말고사: Q13(p.4), Q25(p.7)

V0.2는 객관식 5지선다만 생성한다. 따라서 서술형 교정은 내신에서 어법 평가 비중이 높다는 근거로만 사용하고 출력 형식으로 모방하지 않는다.

## 2. 관찰된 객관식 형식

객관식 13문항 중 11문항은 지문 속 다섯 밑줄 가운데 어법상 틀리거나 옳지 않은 하나를 고르는 형식이었다. 나머지는 같은 문법 구조를 문장 선지로 비교하는 형식 1문항과 여러 밑줄 중 옳은 것들의 조합을 고르는 형식 1문항이었다.

현재 V0.2의 `controlled_error_variant`는 첫 번째 형식, 즉 다섯 밑줄 중 오류 하나를 찾는 구조만 직접 지원한다. 문장 선지 비교형, 복수 정답 조합형, 서술형 고쳐 쓰기는 Schema가 지원하지 않으므로 임의 생성하지 않는다. 향후 별도 계약이 생기기 전까지 이 관찰을 현재 choices나 answerIndex 의미를 바꾸는 근거로 사용하지 않는다.

## 3. 밑줄 범위와 기호

- 실제 밑줄은 한 단어뿐 아니라 동사구, 수동태 구성, 전치사·to부정사 결합 등 문법 판정에 필요한 다중어 범위를 포함했다.
- `testedSpan`과 다섯 `evidenceSpans`는 시각적으로 밑줄 칠 정확한 시작과 끝을 보존한다. 핵심 구성 요소를 잘라 짧은 토큰만 반환하지 않는다.
- 다섯 표적은 원문 순서이고 서로 겹치지 않아야 한다. 문장 전체를 밑줄 범위로 사용하지 않는다.
- 실제 시험지는 `①~⑤`, `ⓐ~ⓔ`, `(a)~(e)` 등 문항별 기호군을 사용했다. 같은 원문에서 삽입 위치와 어법 밑줄이 함께 쓰일 때 서로 다른 기호군도 관찰됐다.
- AI는 관찰된 특정 기호를 고정하지 않고 제작 프롬프트가 각 itemId에 배정한 choices 배열을 그대로 사용한다.
- answerIndex는 기호의 모양이나 내부 boundary 숫자가 아니라 배열의 1~5 순번이다.

## 4. 내신형 다섯 표적 설계

다섯 표적은 원문에서 판정 가능한 범위 안에서 다음 항목을 가능한 한 분산한다.

- 관계대명사·관계부사와 관계절 내부 성분
- 동격 that과 관계대명사 that의 구별
- 실제 주어와 동사의 수 일치
- 동사와 준동사, 목적격 보어, 병렬 구조
- 능동·수동과 분사 형태
- 대명사·재귀대명사의 선행사와 수
- 전치사·접속사·절의 완전성처럼 문법적으로 결정 가능한 구조

다섯 표적을 억지로 모두 다른 범주로 채우지 않는다. 원문에 근거가 없는 범주를 만들지 말고, 판정이 유일한 표적을 우선한다. 단순 철자 손상, 하이픈 제거, 어휘 의미 바꾸기, 희귀어 함정은 어법 오류로 사용하지 않는다. 정답 하나 외 네 표적은 제시형에서 문법상 성립해야 한다.

구체 grammarTarget이 `controlled_error_variant`에 들어오면 우선값이다. 원문에 없을 때는 오류로 거부하지 않고 지원 태그 중 실제 근거가 분명한 구조로 전환한다. `source_form_check`의 구체 태그만 강제 조건이다. 자동·전환 선택 결과는 item, grammar_check, ruleCheck에 같은 구체 태그로 기록한다.

## 5. 원문과 변형 분리

- source.passage, sentence text, evidence text와 sourceForm은 권위 원문을 그대로 보존한다.
- 오류는 `presentedForm`에만 최소한으로 둔다. sourceTextModified는 false다.
- `sourceForm === testedSpan.text`이며, testedSpan은 다섯 evidenceSpans 중 정확히 하나다.
- answerIndex는 testedSpan이 다섯 표적 배열에서 차지하는 순번이다.
- 하이픈과 구두점은 원문 근거를 보존한다. 원문에 있는 하이픈을 삭제하거나 외부 지식으로 새 하이픈을 추측해 넣지 않는다.

## 6. Corpus syntax·discourse 근거

Corpus Engine Generation Runtime Profile V0.4의 syntax·discourse 값은 실제 시험 표면 분포의 보조 근거다. 평균을 목표값이나 quota로 복제하지 않는다.

- 문장 길이와 접속 표현은 soft reference다. 범위 이탈만으로 자동 실패시키지 않는다.
- 긴 문장은 실제 개념·논리·수식 관계에 기여해야 한다.
- 관계절, 분사, 삽입, 동격, 병렬을 통계 수치에 맞추려고 억지로 넣지 않는다.
- 접속어 수보다 문장 간 실제 관계를 우선하고, 명시적 접속어 없는 자연스러운 전개를 허용한다.
- 희귀어와 불필요한 장문으로 난도를 위장하지 않는다.
- 일반 문항은 공유 원문을 한 번만 관리하고, 각 문항의 evidence와 표식은 문항별로 분리한다.

true syntax tree depth, dependency parsing, antecedent resolution, 절대 난이도 보정은 현재 evidence에서 unsupported다. 이를 이미 검증된 통계처럼 주장하지 않는다.

## 7. Vocabulary evidence 경계

시험 어휘 빈도는 `observed_surface`, EBS 등재는 `observed_reference`, 의미·절대 난이도는 `unsupported`로 분리한다.

- EBS 등재를 중요도·필수성·난이도 점수로 해석하지 않는다.
- EBS에 있다는 이유만으로 단어를 요구하지 않고, 없다는 이유만으로 금지하지 않는다.
- 학년별 관찰 분포는 표본 수와 함께 soft reference로만 사용한다.
- 제공 원문의 어휘와 evidence는 vocabularyLevel 때문에 바꾸지 않는다. vocabularyLevel은 새 발문·선지·삽입 문장·해설에만 적용한다.
- source-evidenced 하이픈과 다중어 경계를 보존한다. 검증되지 않은 결합·분리는 하지 않는다.

## 8. 생성 전 자체검수

1. V0.2가 직접 지원하는 다섯 밑줄 단일 오류형인가?
2. 다섯 밑줄은 원문 순서이며 서로 겹치지 않는 정확한 단어·구 범위인가?
3. Request의 item별 choices 기호를 글자 단위로 보존했는가?
4. 정답 하나만 presentedForm에서 문법 오류이고 나머지 넷은 성립하는가?
5. testedSpan, sourceForm, presentedForm, answerIndex가 같은 표적을 가리키는가?
6. 원문·raw evidence를 수정하지 않았는가?
7. 철자·하이픈 손실이나 어휘 의미 함정을 어법으로 위장하지 않았는가?
8. Corpus·EBS 관찰값을 quota, 중요도 또는 절대 난이도로 오해하지 않았는가?

위 조건을 충족하지 못하면 임의 보정한 문항을 출력하지 않는다. Request 자체가 유효하지만 우선 grammarTarget만 원문에 없으면 지원되는 source-evidenced 태그를 선택하고 그 선택을 구조화 필드에 일관되게 기록한다.
