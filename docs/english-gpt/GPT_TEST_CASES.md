# 수능형 전용 GPT 검수 시나리오

## 통과 기준

- 듣기 1~17번을 만들지 않는다.
- 첫 응답은 JSON이 아니라 한국어 `[세트 제작 설계안]`이다.
- 승인 전에는 지문·선지·일부 JSON도 만들지 않는다.
- 수정 요청 뒤 전체 설계안을 다시 보여 준다.
- 승인 뒤에는 JSON 객체 하나만 출력한다.
- `itemId`, `templateId`, `variantId`가 입력과 정확히 같다.
- 일반 지문은 줄바꿈 없는 한 문단이다.
- 35·38·39는 별도 내용 선지 없이 위치 번호만 사용한다.
- 41~42, 43~45는 고정 묶음이다.
- 실제 기출 문장·고유 사례를 복제하지 않는다.

## 1. 승인 절차

앱에서 18번 카드 하나의 프롬프트를 붙여 넣는다.

예상:

- `[세트 제작 설계안]`으로 시작한다.
- 카드의 주제, 장르, 전개, 단어 수, 난도, 정답·오답 논리를 제시한다.
- 정해진 승인 질문으로 끝난다.
- JSON은 없다.

## 2. 설계 수정

`카드 1의 소재를 학교 행사가 아니라 지역 도서관의 프로그램 취소 안내로 바꾸고, 요청 표현은 중후반에 두세요.`

예상:

- 수정한 전체 설계안을 다시 제시한다.
- 승인 전이므로 영어 지문이나 JSON을 출력하지 않는다.

## 3. 승인 후 JSON

`승인. 이대로 JSON 생성.`

예상:

- 첫 글자가 `{`, 마지막 글자가 `}`다.
- 코드 블록과 설명이 없다.
- 앱에서 그대로 가져올 수 있다.
- 일반 지문은 한 줄의 연속 문단이다.

## 4. 다중 카드와 정답 분산

목적 18, 어법 29, 빈칸 33, 복합 장문 43~45 카드를 한 프롬프트로 보낸다.

예상:

- 카드 네 개를 하나의 설계안에서 각각 다룬다.
- 실제 생성 문항 수는 1+1+1+3이다.
- 43~45는 하나의 공유 지문 카드다.
- 승인 후 `items` 네 개를 반환한다.
- 여섯 실제 문항의 정답 위치가 한 번호에 과도하게 몰리지 않는다.

## 5. 구조형 문항

- 35: ①~⑤가 본문 안에 있고 본문 전체는 한 문단이다. `choices`는 번호뿐이다.
- 38·39: 삽입문 상자와 본문만 분리하며 본문은 한 문단이다.
- 40: 원문과 요약문만 분리하며 각각 한 문단이다.
- 43~45: A~D 경계만 유지하며 각 구획 안에는 줄바꿈이 없다.

## 6. 품질과 독창성

빈칸 33번을 생성한 뒤 확인한다.

- 정답이 본문의 핵심 문구를 그대로 복사하지 않는다.
- 네 오답이 각각 다른 오류를 가진다.
- 가장 강한 오답과 정답을 가르는 근거가 명확하다.
- `qualityReview`의 필수 점수가 0~10 범위다.
- 기준 미달이면 한 차례 수정한 결과만 반환한다.
- 업로드된 PDF의 고유명사, 수치 배열, 특징적인 사례가 재사용되지 않는다.

## 7. 재검토

앱에서 생성한 재검토 프롬프트를 보낸다.

예상:

- 새 설계 승인을 요구하지 않는다.
- 타당한 부분은 보존한다.
- 경고를 반영한 수정 JSON 하나만 반환한다.
- `qualityReview`도 새 결과에 맞게 갱신한다.
